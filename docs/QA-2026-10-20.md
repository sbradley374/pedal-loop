# Beta verification, October 20, 2026

## Safari desktop

Verified through the actual interface:

- Generate a 30-mile Providence request: three alternatives rendered, reported search 9.4 seconds.
- Select alternative 02: title, metrics, elevation profile, and GPX link changed together.
- Save the selected ride: confirmation shown.
- Copy ride link: local-server scope message shown.
- Download GPX: Safari Downloads listed a 109 KB export.
- Inspect the rendered desktop results: cards, details, buttons, and elevation profile were legible and aligned.

Safari responsive mode at 390 × 844 CSS pixels showed a single-column preferences form with readable labels, help text, and usable controls, without apparent horizontal overflow. Capture failed during the next scroll, so map/results interaction at mobile width, saved-ride reopening, cancellation, and geolocation permission/error behavior still need a complete browser pass. This was responsive preview, not physical-device testing.

Arc's native automation previously blanked both the app and the script-free health JSON response after input. Safari initially had capture errors but later supported the checks above. Do not infer an app rendering defect from the Arc-only reproduction.
